How it runs

1 · in the agent harness

Hooks write the ledger

Claude Code PostToolUse and Stop hooks (Codex: rollout log adapter) append every tool call, full stdout, exit code, and file path to ~/.custos-code/<session>.sqlite, hash-chained. The model has no write path to this file.

2 · in the Custos Code engine

The ladder settles each claim

The final message is split into claims. Rules check witnessed and outcome (paths, runner output, exit codes, pipes). Test claims are re-run in a worktree. Only the residue reaches a judge, which can say confirmed or unwitnessed, never contradicted.

3 · in VS Code

The Custos Code extension shows it

Watches ~/.custos-code. Mirrors the agent's last message with marks in its own view, decorates touched lines in the editor, fills the Claims / Ledger / Cost panel, and puts the tally in the status bar. It never modifies the agent extension.

4 · back to the agent (auto mode)

Contradictions are handed back

Deterministic nudge templates (zero LLM tokens) name the exact re-run or withdrawal per claim. The report is held until no ✗, ○, or bare ? remains; a mark clears only when new ledger events bear on that claim. Cap: three passes, then the human.

What is deliberate here

  • Unmarked sentences are unmarked on purpose. "Ready to merge" is an opinion, not a claim. Marking everything would train people to ignore marks.
  • ? and ○ are not accusations. A manual browser check leaves no trace; a piped test command hides the result. The mark says "I could not see," and the panel says what would make it visible.
  • Every mark opens to evidence. Tier, method, and ledger line numbers. A verdict without a citation does not exist in this product.
  • The status bar is the whole product in 30 characters. A developer who never opens the panel still sees "1 ✗" before they trust "done".
